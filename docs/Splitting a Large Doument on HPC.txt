# **Parallel Data Splitting on HPC Using GPFS and GNU Parallel**

## **1. Overview**

This document describes a high-throughput, parallelized approach to splitting very large text-based datasets (multi-terabyte TSV or CSV files) into smaller, row-limited chunks on high-performance computing (HPC) systems. The method leverages **GNU Parallel** with **concurrent reads** on **GPFS (IBM Spectrum Scale)**, allowing efficient streaming without intermediate temporary files.

## **5. Split Script**

The following SLURM batch job performs the parallel streaming split:

```bash
#!/bin/bash
#SBATCH --job-name=split_parallel
#SBATCH --account=etur10
#SBATCH --partition=gp_ehpc
#SBATCH --qos=gp_ehpc
#SBATCH --cpus-per-task=64
#SBATCH --mem=512GB
#SBATCH --time=24:00:00

INPUT="/path/to/large.tsv"
OUTDIR="/path/to/output_dir"
LINES_PER_FILE=100000000
HEADER_LINE=2
NCORES=${SLURM_CPUS_PER_TASK:-64}

mkdir -p "$OUTDIR"
HEADER=$(sed -n "${HEADER_LINE}p" "$INPUT")

module load parallel/20231122 2>/dev/null || true

parallel --pipepart -a "$INPUT" -j $NCORES --block 50G --keep-order --line-buffer \
  --header : '
    awk -v header="'"$HEADER"'" -v LINES='"$LINES_PER_FILE"' -v OUTDIR='"$OUTDIR"' -v JOB={#} "
      BEGIN {
          count=0; split_id=1;
          file=sprintf("%s/split_%05d.tsv",OUTDIR,JOB);
          print header > file
      }
      NR>2 {
          print >> file; count++;
          if(count>=LINES){
              close(file); split_id++; count=0;
              file=sprintf("%s/split_%05d_%02d.tsv",OUTDIR,JOB,split_id);
              print header > file
          }
      }
  '
```

**Features:**

* Uses `--pipepart` for concurrent reads directly from the large input file.
* Each process reads 50 GB of the file at a time.
* Writes directly to final split files (no temporary files).
* Automatically inserts header into each output file.
